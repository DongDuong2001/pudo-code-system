# Git Workflow

## Branch Strategy

| Mode | Strategy |
| --- | --- |
| Lite | Commit directly to main or short-lived branch |
| Standard | Feature branches → PR → main |
| Enterprise | Protected main + required reviews + status checks |

## Commits

Use [Conventional Commits](https://www.conventionalcommits.org/) for the PUDO DevOS repository:

```text
feat(workflows): add feature-delivery lifecycle spec
docs(devos): add memory system design
fix(cli): handle missing memory directory
```

Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`

## Pull Requests

- One logical change per PR (or single-file commits on feature branches per team preference)
- PR description includes: scope, test plan, gate status
- Use `.github/pull_request_template.md` (generated by `pudo init`)

## Release Branching

- `main` is always releasable
- Tags follow semver: `v3.0.0`
- MCP package has independent version lifecycle
